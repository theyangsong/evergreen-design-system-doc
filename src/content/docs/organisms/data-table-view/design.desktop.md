# 1. 定位

`eds-org-data-table-view` 是一个**纯展示型**业务表格组件，用于结构化数据的只读展示，并支持**行选择与批处理操作**（如批量导出、批量审核、批量删除等）。它不包含任何行级编辑或复杂状态机，所有数据写入操作通过普通 API 调用完成，不使用 `eds-biz-data-submission`。

## 设计目标

- 提供统一的结构化数据只读展示容器
- 支持表格列配置（宽度、对齐、溢出、排序、拖拽调整列宽）
- 支持行多选（Checkbox）及全选/反选
- 支持批处理（工具栏显示选中数量，触发业务回调）
- 支持固定右侧操作列（文本按钮，最多两个，一个主操作、一个更多）
- 支持列排序、列宽拖拽与钉在左侧
- 支持 Base 数据域绑定（可选，用于权限控制）

## 解决的问题

- 大量交易数据页面只需查看数据，偶尔需要批量处理（如导出、审核）
- 避免为简单批处理引入复杂状态机，降低性能开销
- 统一只读表格的交互规范（多选、工具栏、列宽调整、排序、列固定）
- 解决长表格横向滚动时关键列（如ID）被移出视口的问题

## 使用边界

### **可使用场景**

- 用户端历史记录、交易明细、订单列表
- 后台管理查看详情（审批流、审核页）
- 需要批量导出、批量审核等操作的只读列表
- 数据报表、统计列表
- 列数较多（>10）需要固定关键列的长表格

# 2. 设计决策与演进

## 设计原则

- **只读展示**：不包含任何编辑控件，保持轻量
- **用户可控**：列宽、排序、固定列等个性化设置需持久化
- **一致性**：所有只读表格遵循相同的交互和视觉规范
- **性能优先**：支持可视区域渲染优化，避免大量 DOM 节点

## 设计权衡

- 功能丰富度 vs 实现复杂度 → 选择支持列固定、拖拽、排序
    - 功能丰富度：提供列固定、列宽拖拽、排序等高级交互，提升长表格可用性
    - 实现复杂度：增加开发成本和维护难度，但为用户带来显著效率提升
    - 结论：因为它们是长表格的核心需求，所以选择支持
- 列固定数量限制 vs 灵活性 → 最多固定 1 列
    - 灵活性：允许用户自由固定任意数量的列，完全个性化
    - 限制：固定多列会导致横向滚动混乱和性能问题
    - 结论：最多固定 1 列，避免影响横向滚动和性能。
- 本地存储持久化 vs 隐私 → 只存储非敏感配置
    - 本地存储持久化：保存列宽、固定列等用户偏好，提升体验
    - 隐私风险：存储内容可能包含敏感数据
    - 结论：只存储非敏感配置（列宽、固定列），不存储数据。

## 演进记录

| **阶段** | **核心特征** | **存在的主要问题** |
| --- | --- | --- |
| **阶段一：静态表格** | 纯展示，无交互 | 无法多选、无法批处理 |
| **阶段二：可交互表格** | 增加多选、排序 | 列宽无法保存，重要列滚动消失 |
| **阶段三：当前版本** | 列宽持久化、列固定、批处理 | 已解决上述问题 |

    - 选中数量：见 `batchbar`

2. **批处理设计规范**
    - 见 `batchbar`
3. **批处理行为规则**
    - 异步调用，按钮显示 loading
    - 成功后刷新数据并清空选中
    - 失败使用全局 `Toast` 提示
4. **列固定交互规范**
    - 钉入口：每一列（除最右侧操作列外）的表头提供，悬浮至表头显示。菜单项“钉在左侧”/“取消固定”
    - 视觉效果：固定列右侧边线使用 1px `var(--stroke-outline-deep)`
    - 固定顺序：按用户固定的先后顺序从左到右排列（先固定的列在最左侧）
    - 固定列数量限制：最多 1 列（超出时禁用其他列的固定选项，并提示“最多固定1列”）
    - 固定列与列宽拖拽：固定列同样支持拖拽调整宽度，且宽度变化会重新计算其他固定列的 `left` 偏移
    - 固定列与排序：固定列的表头仍可点击排序
    - 取消固定：取消后该列回到原列区域（保持其原始顺序）

6. **列配置属性（补充）**
    
    
    | **属性** | **说明** | **默认值** |
    | --- | --- | --- |
    | `fixedable` | 是否允许用户固定该列（左侧） | `true`（最右侧操作列固定为 `false`） |
    | `fixed` | 初始是否固定（仅由持久化或设计决定） | `false` |

7. 数据交互
    1. 行限定：一个单元格禁止出现多行数据
    2. 普通溢出：使用“…”
    3. 地址溢出：中间“…”
    4. 复制：悬浮至整行时显示（有复制的字段都要显示iCon）
    5. 完整数据补充：悬浮至单元格时，显示 `Tooltip`（文本+操作按钮）

    | `onRowClick` | `(row: Row) => void` | 可选 | 点击行回调 |
    | `onActionClick` | `(key: string, row: Row) => void` | 可选 | 操作列按钮回调 |
    | `density` | `'compact' | 'normal'` | `'normal'` | 行高密度 |
    | `emptyText` | `string` | `'暂无数据'` | 空状态文案 |
    | `loading` | `boolean` | `false` | 表格数据加载中 |
- **列固定实现要点**
    - 数据结构：维护 `fixedColumnKey` 字符串（最多固定1列，因此无需数组）
    - 左偏移计算：固定列左侧偏移 = 所有左侧列宽之和（如果固定列不是第一列）
    - CSS：固定列使用 `position: sticky; left: {offset}px; z-index: 1;`；表头固定列需额外 `z-index`
    - 拖拽列宽时：重新计算固定列的 `left` 偏移，并更新 DOM
    - 持久化：将固定列 key 存储到 localStorage（键名 `table_fixed_column_{baseId}_{tableId}`）
    - 菜单交互：点击“钉在左侧”时，若当前无固定列，则固定该列；否则提示“最多固定1列”。点击“取消固定”则清空固定列
    - 最右侧操作列：始终固定右侧（`position: sticky; right: 0`），不参与左侧固定逻辑

- **批处理实现示例（React）**
    
    ```tsx
    const handleBatchExport = async (selectedRows) => {
      await api.batchExport(selectedRows.map(r => r.id));
      message.success('导出任务已创建');
      clearSelection();
    };
    
    <eds-org-data-table-view
      columns={columns}
      rows={data}
      selectable
      batchActions={[{ key: 'export', label: '批量导出' }]}
      onBatchAction={({ key, selectedRows }) => {
        if (key === 'export') handleBatchExport(selectedRows);
      }}
    />
    ```
    
- **性能策略**
    - 多选：使用 `Map` 存储选中状态，避免频繁遍历数组
    - 列宽拖拽：使用 `requestAnimationFrame` 节流，避免频繁重排
    - 固定列变化：只重新计算偏移，不整表重绘

# 8. 使用规范

## 允许

- 必须为每个列提供 `key`、`label`、`minWidth`
- 若启用多选（`selectable: true`），必须提供唯一 `rowKey`（默认使用 `row.id`）
- 批处理必须异步实现，并处理错误提示
- 批处理完成后应清空选中状态
- 排序、分页时自动清空选中状态
- 固定列数量不超过 `maxFixedColumns`（默认 1）

## 禁止

- 禁止在只读表格中嵌入编辑控件（输入框、下拉框等）
- 禁止单次批处理超过 99 行
- 禁止固定列数量超过 1 列
- 禁止在操作列使用文字按钮（必须使用图标按钮）

## 约束

| **约束项** | **限制** |
| --- | --- |
| 最大行数 | 100（超出必须后端分页） |
| 最大列数 | 100（组件自带横向滚动） |
| 批处理最大行数 | 99 |
| 操作列按钮 | ≤ 3 个 |
| 最小列宽 | 80px |
| 最大固定列数 | 1 |

# 9. 开发实现

## 技术栈

- 框架 Framework：Vue 3（Composition API）或 React
- 状态管理：组件内部（ref/reactive），无全局 store
- 样式 Styling：CSS Variables + SCSS

## 属性 Props API

| **属性 Prop** | **类型 Type** | **默认值 Default** | **描述 Desc** |
| --- | --- | --- | --- |

| `batchActions` | `BatchAction[]` | `[]` | 批处理按钮配置 |
| `onBatchAction` | `(key: string, rows: Row[]) => Promise<void>` | 可选 | 批处理回调 |
| `onRowClick` | `(row: Row) => void` | 可选 | 点击行回调 |
| `onActionClick` | `(key: string, row: Row) => void` | 可选 | 操作列按钮回调 |

## 状态机

无状态机（只读组件不涉及提交状态）。

## 插槽

- `batchbar`：自定义工具栏（覆盖默认批处理区）
- `cell`：自定义单元格内容（`{ column, row, value }`）
- `action`：自定义操作列内容（`{ row }`）

## 性能

- memo：每行使用 `shallowRef` 或 `React.memo` 避免无意义重渲染
- 渲染 render cost：O(visibleRows)，启用可视区域优化时仅渲染可视区行 + 缓冲
