# 1. 定位

`eds-org-data-list` 是一个**响应式只读数据列表**，用于在固定宽度容器内展示结构化数据。它的核心特征：

- 无横向滚动条
- 列数建议 3～4 列，最多99列
- 响应式适配：
    - 默认展示首、尾列
    - 客户端宽度 ≥ 1120px 时，根据列的最小宽度从左到右依次显示
    - 右侧抽屉 Skid 打开时，隐藏尾列
- 无列固定交互
- 支持多选、批处理、列排序

!data-list-about.png

图例：多选、`BatchBar`、列排序

## 设计目标

- 简易数据的容器，专注于结构化数据的清晰呈现
- 支持行批处理操作，提升数据处理效率
- 支持列排序，方便数据查阅
- 支持响应式适配，保障不同屏幕尺寸下的可用性
- 支持 Base 数据域绑定（可选，用于权限控制）

## 解决的问题

- 列表列数受限时，数据错乱
- 批处理交互路径不一致
- 列表详情查看不统一
- 右侧抽屉打开时，列表列空间被挤压，加剧数据错乱

## 使用边界

### **可使用场景**

- 客户端简易数据列表
- 后台管理简易数据列表
- 需要批处理操作但列数较少的只读列表

### **不适用场景**

- 复杂数据展示，数据统计需要 → 应使用 `eds-org-data-table-view`
- 需固定特有列来完成数据核对 → 应使用 `eds-org-data-table-view`
- 行内编辑、批量提交数据需要 → 应使用 `eds-org-data-table-edit`

# 2. 设计决策与演进

## 设计原则

- **无横向滚动**：所有列宽度之和 ≤ 容器宽度，不提供横向滚动条
- **渐进显示**：从首列开始，根据最小宽度从左到右依次显示更多列
- **一致性**：所有列表遵循相同的交互和视觉规范

## 设计权衡

- **无横向滚动 vs 信息密度 → 渐进显示优先**
    - 无横向滚动：避免用户左右拖拽
    - 信息密度：通过响应式适配，在屏幕够宽时显示更多列，不够时仅显示首列、尾列
- **列数限制 vs 灵活性 → 建议 3～4 列**
    - 保证常见屏幕下可显示大部分列，避免溢出
    - 尽可能保证数据完整展示
- **抽屉联动 vs 列完整性 → 抽屉打开时隐藏尾列**
    - 保证操作区域不被遮挡，牺牲尾列的可见性
    - 抽屉展开时关注重点在 `Skid` 里的内容

## 演进记录

| **阶段** | **核心特征** | **存在的主要问题** |
| --- | --- | --- |
| **阶段一：静态列表** | 纯展示，无交互 | 无法多选、无法批处理 |
| **阶段二：可交互列表** | 增加多选、排序 | 无响应式适配，小屏幕溢出 |
| **阶段三：当前版本** | 响应式适配（渐进显示+抽屉联动）、批处理标准化 | 已解决上述问题 |

#### **详细交付指南**

1. **多选交互规范**
    - 表头 Checkbox：点击全选/全不选；部分选中时半选状态（indeterminate）
    - 行 Checkbox：点击选中/取消选中当前行
    - 视觉反馈：选中行无背景色变化，仅复选框状态改变。
    - 选中数量：下方批处理工具栏显示“已选 X 项”
    
2. **批处理设计规范**
    - 见 `batchbar`
3. **批处理行为规则**
    - 异步调用，按钮显示 loading
    - 成功后刷新数据并清空选中
    - 失败使用全局 `Toast` 提示
    - 当前页触发多选，则禁用翻页。取消全选后恢复
    - 操作项超 `4` 项时，使用 More 承载
    - 操作项里有 `删除` 时，应强调该操作
    - 操作触发的业务交互使用 `插槽` 拓展

4. **响应式适配规则（核心）**
    - **基础逻辑：**
        - 列表默认只显示首列、尾列数据
        - 当客户端宽度 ≥ 1120px 时，根据列的 `minWidth` 计算，**从左到右**依次显示更多列，直到容器宽度不足再显示下一列
        - 当右侧抽屉（Skid）打开时，**隐藏尾列**
    - **断点规则表：**
        
        
        | 断点 | **列显示行为** |
        | --- | --- |
        | 默认尺寸 | 从左到右计算：每列按 `minWidth` 累加，能放下几列就显示几列（强制：首列+尾列） |
        | 客户端宽度 ≥ 1120px | 从左到右计算：每列按 `minWidth` 累加，能放下几列就显示几列（至少首列） |
        | 右侧抽屉打开 | 在上述基础上，隐藏尾列 |
        | 宽度变化（窗口resize、侧边栏展开/收起） | 重新计算列可见性，平滑过渡 |

图例：默认仅展示 `首&尾` 列
<br><br>
        
5. **操作列规范**
    - 位置：最右侧
    - 数量：最多 2 个文本按钮
        - 主按钮：核心业务操作（如“编辑”、“审核”）
        - 次按钮：“更多” 按钮，点击展开下拉菜单，收纳其余操作（如“删除”、“复制”、“分享”等）
    - 交互：点击按钮触发对应的回调
    - 规则：按钮数量的显示规范
        - 按钮数为 `1`：以“主按钮”的样式进行展示
        - 按钮数为 `2`：“更多”这个次按钮应显示具体的操作
    
6. **详情 `Detail` 联动**
    - 触发方式：点击列表行任意位置

- **响应式适配实现要点**
    - 监听客户端宽度：使用 `ResizeObserver` 监听列表根元素宽度
    - 监听 Skid 抽屉状态：通过全局状态或事件总线获知抽屉是否打开
    - 列可见性计算：
        - 基础逻辑：从左到右遍历列，累加 `minWidth`，直到超出容器宽度为止
        - 当抽屉打开时，从计算结果中移除尾列
    - 无列宽拖拽：因此无需处理列宽变化
    
    ```tsx
    // 伪代码
    function getVisibleColumns(columns, containerWidth, isSkidOpen) {
      let totalWidth = 0;
      const visible = [];
      const nonActionCols = columns.filter(c => !c.isAction);
      for (let col of nonActionCols) {
        if (totalWidth + col.minWidth <= containerWidth) {
          visible.push(col);
          totalWidth += col.minWidth;
        } else break;
      }
      if (isSkidOpen && visible.length > 1) {
        visible.pop(); // 隐藏尾列
      }
      return visible;
    }
    ```
    
- **批处理实现示例（React）**
    
    ```tsx
    const handleBatchExport = async (selectedRows) => {
      await api.batchExport(selectedRows.map(r => r.id));
      message.success('导出任务已创建');
    };
    
    <eds-org-data-list
      columns={columns}
      rows={data}
      selectable
      batchActions={[{ key: 'export', label: '批量导出' }]}
      onBatchAction={({ key, selectedRows }) => {
        if (key === 'export') handleBatchExport(selectedRows);
      }}
    />
    ```

# 6. 交互行为

| **行为** | **触发** | **响应** |
| --- | --- | --- |
| 行悬停 | 鼠标移入 | 显示 `hover` 高亮 |
| 行无数据时 | 鼠标移入 | 不显示 `hover` 高亮 |
| 列排序 | 点击列标题（`sortable: true`） | 重新请求数据，清空选中 |

| 行选中 | 点击行 Checkbox | 更新复选框状态，批处理工具栏显示选中数量 |

# 8. 使用规范

## 允许

- 必须为每列提供 `key`、`label`、`minWidth`
- 列数建议 3～4 列，最多99列
- 所有列宽之和应保证在最小宽度下只显示首列+尾列
- 多选/批处理异步实现，完成后清空选中
- 操作列核心按钮 + 更多菜单收纳其他操作

## 禁止

- 禁止出现横向滚动条
- 禁止单次批处理超过 99 行
- 禁止在单列模式下无详情入口（点击行必须响应）
- 禁止操作列超过 2 个按钮（核心 + 更多）

## 约束

| **约束项** | **限制** |
| --- | --- |
| 最大行数 | 100（超出必须分页） |
| 最大列数 | 99（建议 3～4） |
| 批处理最大行数 | 99 |
| 操作列按钮 | ≤ 2 个（核心 + 更多） |
| 最小列宽 | 80px |

# 9. 开发实现

## 技术栈

- 框架：Vue 3（Composition API）或 React
- 状态管理：组件内部
- 样式：CSS Variables + SCSS
- 响应式：`ResizeObserver` + 全局抽屉状态（如 Pinia store）

## Props API

| **Prop** | **类型** | **默认值** | **描述** |
| --- | --- | --- | --- |
| `baseId` | `string` | 可选 | Base ID |
| `columns` | `Column[]` | 必填 | 列定义（含 `minWidth`） |
| `rows` | `Row[]` | `[]` | 行数据 |
| `selectable` | `boolean` | `false` | 是否启用多选 |
| `selectedRowKeys` | `string[]` | `[]` | 受控选中 |
| `onSelectionChange` | `(keys) => void` | 可选 | 选中回调 |
| `batchActions` | `BatchAction[]` | `[]` | 批处理配置 |
| `onBatchAction` | `(key, rows) => Promise` | 可选 | 批处理回调 |
| `primaryAction` | `{ icon, onClick }` | 可选 | 核心操作按钮 |
| `moreActions` | `Action[]` | `[]` | 更多菜单操作项 |
| `onRowClick` | `(row) => void` | 可选 | 行点击回调 |
| `density` | `compact / normal` | `'normal'` | 行密度 |
| `emptyText` | `string` | `'暂无数据'` | 空文案 |
| `loading` | `boolean` | `false` | 加载中 |

## 状态机

无状态机（只读组件不涉及提交状态）。

## 响应式适配关键代码（概念）

```tsx
const useResponsiveColumns = (columns, containerRef, isSkidOpen) => {
  const [visibleColumns, setVisibleColumns] = useState([]);
  useResizeObserver(containerRef, (entry) => {
    let width = entry.contentRect.width;
    let temp = [];
    let total = 0;
    for (let col of columns) {
      if (total + col.minWidth <= width) {
        temp.push(col);
        total += col.minWidth;
      } else break;
    }
    if (isSkidOpen && temp.length > 1) temp.pop();
    setVisibleColumns(temp);
  });
  return visibleColumns;
};
```

## 性能

- 多选使用 `Map`
- 响应式适配防抖 100ms
- 行数 > 200 时启用虚拟滚动
